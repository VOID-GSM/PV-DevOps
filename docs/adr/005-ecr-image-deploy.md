# 005. 서버 빌드 대신 ECR 이미지 배포 + 자동 롤백
Status : Accepted
Date : 2026-10 

## Context
기존에는 소스를 S3에 올리고 EC2에서 Gradle로 빌드했다. **빌드 중 메모리를 많이 써서 운영 중인 서비스가 OOM 위험에 노출됐다.** 이미지에 버전이 없어 이전 버전으로 되돌릴 방법이 없었고 ECR을 만들어 두고 사용하지 않았다.

## Decision
GitHub Actions의 ARM 러너에서 arm64 이미지를 빌드해 커밋 SHA 태그로 ECR에 push한다. ECR은 태그 불변, 최근 10개 이미지만 유지한다. 서버는 SSM 배포 문서로 이미지를 pull해서 `docker compose up --wait`로 교체한다. 헬스체크에 실패하면 직접 성공 태그로 자동 롤백한다. 그리고 배포 문서의 `tag` 파라미터는 커밋 SHA 형식만 허용한다.

## Alternatives
대안 | 버린 이유
--- | ---
서버 빌드 유지 | OOM 위험, 롤백 불가
x86 러너 + QEMU로 ARM 빌드 | 에뮬레이션으로 빌드가 느림. 공개 레포는 ARM 러너를 무료로 사용 가능

## Consequences
**얻은 것** : 운영 서버의 빌드 부하 제거. 실행 중인 버전을 커밋 SHA로 추적. 실패 시 자동 롤백.

**감수한 것** : 
- **헬스체크는 포트 오픈만 확인** : DB 연결 실패 같은 문제는 감지하지 못함. → Actuator 헬스 엔드포인트로 개선 예정
- 롤백 가능한 범위는 ECR에 남아 있는 최근 10개의 이미지
- 배포 전 테스트 게이트가 아직 없다. → 백엔드 CI에 테스트 단계 추가 예정
